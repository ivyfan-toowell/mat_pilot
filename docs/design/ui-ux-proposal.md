# MatPilot UI / UX 设计方案

日期：2026-11-04。范围：基于现有五个工作区的设计规范、响应式布局与交互预览。

实现进展：基础主题、电脑侧栏 / 手机底栏、五个工作区、文献名称选择、实验与历史任务回读、原文弹窗和输入保留已接入运行中的 Streamlit 应用，地址仍为 http://127.0.0.1:8501。实际截图及浏览器记录见 data/acceptance/ui-live-20261104/。真实任务流式进度、取消、跨设备历史和手机可访问部署仍属后续能力，不能与已经完成的界面改造混淆。

## 1. 产品定位与设计目标

将 MatPilot 设计为安静、清晰、可追溯的材料科研工作台。视觉以米白、浅灰、浅棕为主体，使用少量雾蓝和豆绿，强调阅读、材料与论文的比较、结论到来源的核查。

- 统一：五个工作区使用同一套导航、间距、字号、按钮和状态语义。
- 克制：每个操作区只设置一个主按钮；避免大面积高饱和颜色、装饰渐变、营销式首屏和无意义统计卡片。
- 渐进：先显示任务和结果，高级参数、技术轨迹、完整 JSON 按需展开。
- 连续：跨页面保留当前文献、查询条件和结果；系统内部关联 ID，用户通过标题、文件名选择对象。
- 可核查：计算数据、实验估计值、在线元数据分别标注；引用匹配与科研人工审核分开表达。

## 2. UI 设计规范

| 装饰分隔线 | #DED8D0 | 卡片与列表的轻量分隔 |
| 输入边界 | #9A9084 | 需要识别边界的表单控件 |
| 雾蓝文字 / 底色 | #526A78 / #E8EDF0 | 原文证据、论文实验信息 |
| 豆绿文字 / 底色 | #536650 / #E8EDE6 | 已完成步骤、证据匹配状态 |
| 柔琥珀文字 / 底色 | #8A6133 / #F3ECE1 | 待审核、需要处理的提醒 |

大面积区域保持中性；语义颜色只用于小面积标签、图标、提示。标签必须有文字，不能只凭颜色传达状态。普通正文与实际背景的对比度目标不低于 4.5:1；装饰线不能替代具有足够辨识度的输入边界。

### 2.2 字体与排版

- 首选字体：微软雅黑，CSS 为 `"Microsoft YaHei", "微软雅黑", sans-serif`；按钮、输入框、表格与弹窗统一继承。
- 字重以 400 为主，标题与选中项使用适度强调，避免大面积粗体和细体。
- 电脑页面标题 28 px，手机 24 px；模块标题 18–20 px；电脑正文 15 px，手机正文与输入内容 16 px；辅助文字 13–14 px。
- 正文行高 1.6–1.75，表单标签 1.45；长论文标题自然换行，不以缩小字号解决溢出。
- 长答案的阅读宽度控制在约 60–72 个拉丁字符对应的范围；数据表格可更宽。数值采用等宽数字排列，但沿用同一字体。
- 化学式与单位保持规范，例如 TiO₂、3.42 eV、eV/atom；复制与提交时保留后端需要的标准表达。
- 手机是否能实际显示微软雅黑取决于字体是否可用。跨平台严格统一时需准备具有网页嵌入使用权限的字体资源；在资源未提供时使用系统无衬线中文字体作为回退，不能声称手机已经加载微软雅黑。

### 2.3 布局、留白与形状

- 间距采用 4 px 基准：4、8、12、16、24、32、48。
- 电脑内容区横向留白 24–32 px，手机 16 px；区块间距 24–32 px，卡片内边距电脑 24 px、手机 16 px。
- 卡片圆角 12–14 px，输入框与按钮 10 px，弹窗 16 px，标签 6 px。
- 卡片默认使用轻边框，必要时加 `0 4px 16px rgba(56,53,47,.045)` 阴影。避免所有容器都套卡片、过深阴影或大面积悬浮效果。
- 图标采用统一线性风格，建议 20 px、约 1.75 px 描边；图标与文字并用。不可只用图标表示关键操作，不以 emoji 充当主导航图标。

### 2.4 组件规范

| 组件 | 统一视觉 | 交互与反馈 |
| --- | --- | --- |
| 导航 | 浅暖灰或暖白底，当前项使用浅棕底、深色文字 | 保留当前位置；切换后焦点和页面标题明确；手机使用同序短标签 |
| 主按钮 | 灰棕填充、暖白文字、10 px 圆角 | 电脑高 40–44 px，手机高 48 px；提交中禁用重复点击并保留动作文案 |
| 次按钮 / 文字按钮 | 轻边框或透明底 | 导出、查看来源、重试等操作不能与主按钮争夺注意力 |
| 输入框 | 暖白底、明确边界、顶置标签 | 占位符仅作示例；必填、单位、限制可见；失焦或提交时就地校验 |
| 卡片 | 暖白表面、轻边框、12–14 px 圆角 | 标题、关键内容、状态、操作四层；整卡可点时仍提供明确操作名称 |
| 标签 | 低饱和浅底、深色文字、6 px 圆角 | 固定语义：计算数据、实验估计、在线元数据、证据已匹配、待人工审核 |
| 列表 / 表格 | 轻横分隔、稳定列宽与对齐 | 桌面可排序、选择；手机转摘要卡，保留详情入口与全部字段 |
| 详情 | 名称与状态在上，核心属性居中，来源在后 | 桌面侧栏或并排，手机独立详情层；返回保留滚动位置 |
| 弹窗 / 抽屉 | 统一暖白表面、16 px 圆角、轻遮罩 | 用于短设置和确认；长原文转详情页。支持 Esc、关闭按钮和焦点恢复 |
| 通知 | 使用轻量状态图标与文字，警告有具体动作 | 短成功提示可消失；错误和重要科研提醒保持可见直到处理 |
| 引用 | 小型编号按钮或链接，雾蓝强调 | 点击直接定位文献、页码及原文范围；返回后继续阅读原答案 |

禁用控件应附原因。键盘焦点保持清晰的 2 px 轮廓，不取消原生可访问焦点样式。

## 3. 信息架构与主路径

保留现有五个业务入口，不引入与现有能力无关的首页看板：

1. 材料筛选：查询、查看、选择候选材料及比较。
2. 论文发现：检索在线元数据、核查访问方式、取得合法可用全文。
3. 论文解析：上传、解析、查看页码、提取实验信息。
4. 文献知识库：入库、检索证据、基于证据回答。
5. 科研助手：提出综合问题、选择来源、查看论断和工具轨迹。

主路径 A：材料筛选 → 选择候选 → 带入科研助手 → 比较论文实验证据。

主路径 B：发现论文 → 查看原文入口 → 取得 PDF 后上传 → 解析并加入知识库 → 提问 → 点击引用核查。

主路径 C：选择已有文献 → 科研助手 → 自动选择简单或协作流程 → 查看结论与证据 → 回读历史任务。

全局研究上下文保存当前文献、已选材料与最近任务；用户通过标题和文件名选择，ID 放在“来源与技术详情”中供复制。跨页携带上下文不意味着自动发起付费任务。

## 4. 电脑端布局

- ≥1200 px：顶部栏 64 px，左侧导航约 216 px，中部主内容自适应，打开来源时右侧证据栏约 320–360 px。
- 768–1199 px：导航收窄或折叠，保留“内容 + 按需详情”两区；容不下时来源改为覆盖式抽屉，不压缩正文和表单到不可读。
- 最大内容宽度约 1440 px，超宽屏居中；阅读正文另设较窄上限。
- 顶部显示当前工作区、当前文献与真实服务状态；系统级提示不占据主要任务区域。
- 筛选与结果相邻，筛选较多时使用可折叠区域。结果上方显示实际生效的条件、排序、选中数量和重置操作。
- 侧栏负责全局导航，页面内标签负责局部视图；不把两层导航混在一组控件里。

## 5. 手机端布局

- <768 px：单列内容、约 56 px 顶栏、五项底部导航，标签为“材料 / 发现 / 解析 / 知识库 / 助手”。可访问名称仍使用完整工作区名称。
- 页面四周 16 px 留白；标题、关键状态、主动作优先。筛选放入底部面板或独立设置层，关闭后显示已应用条件摘要。
- 每个触控目标设计为至少约 44 × 44 px，主要按钮高 48 px；横排按钮放不下时换行，不缩小字体。
- 材料表格改为摘要卡：化学式、关键数值、数据类型、比较选择；其余字段进入详情。
- 原文、实验记录和引用详情一次展示一层；打开详情后有明确返回操作，不在窄屏叠放多个面板。
- 常用主动作在安全区内可达；底部操作条与底部导航不能同时堆叠遮挡正文，应合并或在任务编辑状态下临时收起导航。
- 考虑 `safe-area-inset-bottom`、软键盘、横竖屏、长英文标题及浏览器缩放。输入框不因聚焦产生布局跳动。
- 文档阅读、证据核查与轻量查询优先适配手机，复杂大表比较仍保留完整能力及逐项查看入口。

这是同一产品的响应式布局，不是把桌面三栏等比例缩小。布局验收至少覆盖 320、375、390、768、1024、1440 px，以及 200% 缩放。

## 6. 核心页面设计

| 页面 | 电脑端 | 手机端 | UX 重点 |
| --- | --- | --- | --- |
| 材料筛选 | 顶部查询，侧边或折叠筛选，结果表与详情并排 | 查询在上，筛选面板，结果摘要卡 | 显示实际条件；不自动放宽范围；选择候选后再进入比较 |
| 论文发现 | 宽搜索框，结果纵向列表，年份/OA/排序轻量化 | 搜索优先，筛选折叠，论文卡自然换行 | DOI 可直接粘贴；区分 DOI、原文页和可用 PDF；明确仅取得元数据 |
| 论文解析 | 左原文、右实验记录，页码和证据双向定位 | “原文 / 实验记录”分段切换，证据全屏详情 | 上传→解析→提取→入库逐步引导；扫描件明确提示待 OCR；保留上传内容与错误原因 |
| 文献知识库 | 提问框、简洁答案、旁侧证据，设置默认折叠 | 提问与答案单列，引用编号打开详情 | 用文献名称选范围；策略显示“语义 / 关键词 / 混合”；额外重排调用显式告知 |
| 科研助手 | 提问与结果为主，任务阶段及历史置于辅助区 | 上下阅读，来源与执行详情按需展开 | 默认推荐自动路由，但由用户提交后才执行；必须来源放到高级设置；结论先于原始轨迹 |

助手结果分为“结论、证据、局限、执行详情”。默认使用可读的属性列表和引文，不直接显示整段 JSON；技术结果仍可展开或下载。历史任务应逐步改为可搜索列表，手填 ID 作为兼容入口。

## 7. 交互逻辑与状态反馈

| 状态 | 应呈现内容 | 可执行动作 |
| --- | --- | --- |
| 首次进入 | 一个明确任务入口与少量问题示例，示例不自动执行 | 填写条件或选择已有文献 |
| 输入无效 | 错误字段旁说明具体原因，保留其他输入 | 修正后再次提交 |
| 加载 | 保持页面框架稳定，显示当前真实阶段 | 避免重复提交；仅在后端支持时提供真正取消 |
| 成功 | 就地展示结果及来源，简短完成反馈 | 查看详情、核查证据、导出、继续下一步 |
| 无结果 | 重述当前生效条件，给出具体调整建议 | 用户主动修改条件，不静默扩大检索 |
| 部分完成 | 显示已完成与失败部分，标记可用范围 | 仅在幂等边界明确时重试失败部分 |
| 失败 | 说明失败环节及可恢复动作，保留条件和既有结果 | 重试、查看诊断、返回编辑 |
| 证据不足 | 明确说现有证据不能支持回答 | 补充全文、调整问题或增加来源 |
| 超时 | 区分请求超时与任务实际状态未知 | 查询真实任务状态；未支持任务查询时不承诺后台仍在运行 |

阶段可采用“收集资料 → 分析 → 引用校验 → 复核 → 完成”，但必须由后端事件驱动，不能使用虚假的百分比或定时器模拟实际进度。
长任务已走 `POST /api/v1/jobs/*` + 状态轮询（界面 `run_job` / `wait_job`）；文献与历史任务列表接口已有。
仍属后续：真实流式阶段推送、任务取消、断线后跨进程恢复执行、跨设备同步。

切换页面时保留表单与结果，不清空整个工作区。修改条件后将旧结果标记为“对应上次条件”，成功取得新结果后再替换；旧结果不得伪装成新查询结果。手机系统返回键与页内返回应回到相同上下文。

过渡建议 160–220 ms，仅用于抽屉、展开和状态变化；遵循减少动态效果偏好，避免持续闪烁、跳动和整页淡入。图表与数值不得靠动画制造结论更可靠的错觉。

## 8. 科研可信度与易用性

- 数据类型与审核状态分别标注：例如“论文实验估计”“证据已匹配”“待科研审核”，不能合并为“已验证准确”。
- 结论中的每个引用可点到文献、页码与原文范围；读完可返回原答案位置。
- 未报告、未提取、当前片段未证实分别表述；空值不自动显示为 0，也不代表论文全文缺失。
- 计算值与实验值保留来源、方法和单位；不在卡片中隐藏会改变解释的条件。
- 检索分数归入排序详情，不表现成科研置信度。
- 系统内部处理 UUID 和工具名，用户界面使用文件名、论文标题与自然语言任务。
- 主操作前说明是否调用模型或触发额外重排；恢复页面不自动重跑已完成任务。
- API 不可用时在仍运行的 UI 中显示状态与重试。若 UI 服务本身未启动，浏览器无法显示应用内提示，应由启动器检测并在服务就绪后打开页面。

## 9. 落地顺序与技术边界

### 第一阶段：视觉与现有流程改进

先在现有 Streamlit 中统一主题、字体、导航与页面标题，再逐页改造表单层级、空状态、列表、引用和结果展示。提取共享设计令牌及页面组件，保留现有 FastAPI 与科研数据校验。能用原生能力完成的交互优先使用原生组件，减少对易变内部 DOM 的样式依赖。

### 第二阶段：补足交互所需接口

**已落地：** 文献与历史任务列表、`GET /api/v1/jobs/{job_id}`、进程内 JobWorker。
**仍缺：** 细粒度进度事件、取消、崩溃后跨进程恢复；阶段 JSON / job 落盘尚不能等同于可恢复分布式队列。

### 第三阶段：完整移动端体验

若原生界面难以满足底部导航、精确抽屉、独立证据阅读与连续任务体验，再评估独立响应式前端；沿用现有 API、证据模型和设计令牌，不以更换前端为前提重写科研逻辑。

手机实机访问与响应式布局是两件事。当前服务只绑定电脑的 127.0.0.1；手机上的 127.0.0.1 指向手机自身。
手机实用部署需准备可访问的地址，并配套 `AUTH_MODE=api_key` 与 HTTPS；默认本机租户模式不能直接当作公开服务。

### 验收清单

- 五个工作区的颜色、字体、按钮、字段与状态标签一致。
- 320–1440 px 无整页横向溢出，长标题、错误文案和数值单位不截断关键内容。
- 主要控件可触控、可键盘操作、焦点可见；弹窗可关闭并恢复焦点。
- 空、加载、成功、失败、无结果、证据不足状态均有可执行的下一步。
- 页面切换、返回和恢复不会意外清空输入、错用旧结果或重复付费调用。
- 计算 / 实验 / 元数据和引用匹配 / 科研审核的语义保持准确。
- 在桌面 Edge、手机 Safari/Chrome 实机核对字体、输入键盘、滚动和安全区；浏览器窄视口检查不能代替实机验收。

## 10. 方案预览说明

对话内提供“电脑工作台”和“手机工作台”两个视图，使用相同配色与组件。支持切换工作区、查看检索设置和打开来源详情，所有交互仅为本地设计演示，不调用模型或执行真实查询。

预览引用已有验收论文 DOI 10.3390/nano10030546 的样例：TiO₂-24 为 3.42 eV、TiO₂-48 为 3.09 eV，原文位于第 5 页表 1。它们是论文实验估计值，不是新生成的科研数据或实时查询结果。

参考：[W3C 文本对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[Microsoft YaHei 字体资料](https://learn.microsoft.com/en-us/typography/font-list/microsoft-yahei)。
